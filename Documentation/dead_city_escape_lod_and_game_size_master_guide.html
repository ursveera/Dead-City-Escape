1. LOD Guide Purpose

This section explains how LODs, also called Level of Detail, should be created for Dead City Escape.

The goal is to keep the game looking good while also keeping performance strong for both PC and mobile.

2. What is LOD?

LOD means different versions of the same model are shown depending on camera distance.

Distance Model Used Detail Level
Near camera LOD0 Highest detail
Medium distance LOD1 Medium detail
Far distance LOD2 Low detail / optimized distance mesh

LOD improves FPS, memory usage, multiplayer stability, and mobile performance.

3. Important LOD Rule

Do not redraw the full model separately for every LOD.

Create one main model first
↓
Duplicate model
↓
Reduce polygons
↓
Create LOD1
↓
Reduce more
↓
Create LOD2
Correct method: Create LOD0 first, then duplicate and simplify it to make LOD1 and LOD2.

4. Professional Character Workflow

Step 1 — High-Quality Source Model

First create a high-detail source model. This can include sculpt details, folds, wrinkles, straps, surface damage, and realistic details.

This source model is usually not used directly inside Unity. It is used for baking details into the game-ready mesh.

High-quality source model
Possible polygon count: 1 million+ polygons

Step 2 — Game-Ready PC Mesh / LOD0

Create the optimized PC game mesh from the source model.

LOD0 target for main survivor:
60k–90k triangles

LOD0 should contain full silhouette quality, facial detail, clothing folds, equipment details, straps, gloves, holsters, boots, and proper animation topology.

Step 3 — Create LOD1

Duplicate LOD0 and reduce the polygon count.

LOD1 target for main survivor:
30k–45k triangles

Reduce small folds, tiny bevels, hidden faces, extra loops, and very small accessories.

Step 4 — Create LOD2

Duplicate LOD1 or LOD0 and reduce polygons further.

LOD2 target for main survivor:
10k–20k triangles

Remove tiny geometry details, unnecessary loops, complex curves, extra pockets, small straps, and detailed wrinkles.

8. Blender Workflow

Manual Method — Recommended

1. Create LOD0
2. Duplicate object
3. Rename duplicate as LOD1
4. Reduce polygons manually or using modifiers
5. Duplicate again
6. Rename as LOD2
7. Reduce polygons further
8. Check silhouette
9. Export to Unity

Decimate Modifier Method

In Blender, use:

Modifier
→ Decimate

10. Character Topology Rule

For characters, do not destroy topology around animation areas.

  • Shoulders
  • Elbows
  • Knees
  • Hips
  • Neck
  • Hands
  • Face
Bad topology causes broken animations, ugly deformation, shadow problems, and skinning issues.

13. PC and Mobile Asset Workflow

Do not create separate PC and mobile models from the beginning.

High-quality source model
↓
PC game-ready optimized mesh
↓
Create LODs
↓
Create mobile optimized version later
Create PC-quality source first. Later reduce it for mobile.

14. Mobile Optimization

For mobile versions, reduce:

  • Polygon count
  • Texture size
  • Shader complexity
  • Material count
  • Transparency usage
  • Realtime lighting usage

Recommended mobile survivor target:

20k–45k triangles

15. Final LOD Instruction

  1. Create high-quality source model first.
  2. Create game-ready PC mesh.
  3. Create LOD1 and LOD2 from the same mesh.
  4. Later create mobile optimized version.
  5. Do not redraw the full character separately for every LOD.
This is the correct professional workflow for real game production.

16. Game Size Guide Purpose

This section explains the approximate game size target for Dead City Escape on PC and mobile.

The purpose is to guide 3D asset creation, texture resolution, optimization, LODs, audio usage, and Unity build size planning.

This is not the exact final size. The exact size will depend on final textures, audio, animations, lighting data, video files, and Unity compression settings.

24. What Makes Game Size Large?

Item Why It Increases Size Control Method
4K TexturesVery large when used for many props and environments.Use 4K only for hero assets. Use 1K/2K for most assets.
Unique MaterialsToo many unique textures increase build size.Use shared tileable materials and trim sheets.
AudioMusic and voice files can become very large.Compress audio and avoid unnecessary long uncompressed tracks.
AnimationsMany unique animations increase size.Reuse animation sets when possible.
Video CutscenesHigh-resolution video takes a lot of storage.Use real-time cutscenes where possible.
Lighting DataBaked lighting can increase size.Use sensible lightmap resolution and area-based loading.
Duplicate AssetsSame asset saved multiple times wastes space.Use prefabs, shared materials, and clean project folders.

25. Optimization Rules for 3D Artist

  • Create modular assets instead of one huge environment mesh.
  • Use shared materials whenever possible.
  • Use tileable textures for roads, walls, floors, concrete, brick, metal, and hospital tiles.
  • Use trim sheets for repeated edges, panels, signs, doors, and wall details.
  • Use LODs for vehicles, zombies, hero props, and repeated large props.
  • Use simple collision meshes.
  • Do not add geometry detail where a normal map can show the same detail.
  • Do not export hidden objects, cameras, lights, or unused meshes.
  • Keep pivot and scale correct before export.
  • Always test asset scale against a 1.8m human reference.

27. Recommended Build Plan

Stage 1 — PC Prototype First

  • Build the first demo for PC first.
  • Use placeholder/blockout assets first.
  • Integrate first optimized assets.
  • Keep PC demo below 5 GB.

Stage 2 — Mobile Test Later

  • After PC demo works, create mobile test build.
  • Reduce textures to mobile sizes.
  • Reduce zombies and prop density.
  • Use baked lighting and fewer realtime effects.
  • Keep mobile demo below 1.5 GB.

Stage 3 — Full Production

  • Build areas one by one.
  • Use addressables or area-based loading later if needed.
  • Keep PC full game around 10–20 GB.
  • Keep mobile full game around 2–4 GB.

28. Final Recommendation

For Dead City Escape, do not try to create PC and mobile final versions at the same time from day one.

First, create the PC-quality vertical slice. After gameplay works, create reduced mobile versions of the same assets.

This gives better quality control and avoids wasting time creating mobile assets before the gameplay direction is confirmed.

Final target:
First PC demo: below 5 GB
First mobile demo: below 1.5 GB
Full PC game: 10 GB – 20 GB
Full mobile game: 2 GB – 4 GB
